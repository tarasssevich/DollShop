## 2. Сетевая инфраструктура и серверный периметр

- [x] **Изоляция СУБД:** Порт PostgreSQL `5432` открыт **только** внутри закрытой Docker-сети `dollshop-net`. Внешний доступ через публичный IP заблокирован UFW (`ufw deny 5432`).
- [x] **Non-Root контейнеры:** Приложение Next.js собирается в многостадийном `Dockerfile` и выполняется под непривилегированным пользователем `nextjs` (UID:GID `1001:1001`).
- [x] **SSH и Fail2ban:** Авторизация по SSH исключительно по ключам Ed25519 (`PasswordAuthentication no`). Утилита `fail2ban` блокирует IP после 3 неудачных попыток входа на 24 часа.
- [x] **HTTPS и TLS 1.3:** Nginx настроен с поддержкой TLS 1.2 и TLS 1.3 с современными шифрами (ECDHE-ECDSA-AES128-GCM-SHA256 и др.). Автоматическое продление сертификатов Certbot Let's Encrypt.
- [x] **Защита от DoS и Brute-Force:** В Nginx настроены зоны `limit_req_zone` (до 20 req/s с burst 40 для динамических путей) и лимитирование соединений `limit_conn_zone`.

## 3. Заголовки безопасности HTTP (Оценка A+ на SecurityHeaders)

В конфигурации обратного прокси `deploy/nginx/conf.d/default.conf` установлены заголовки:

```nginx
# Защита от встраивания в iframe (Clickjacking)
add_header X-Frame-Options "DENY" always;

# Защита от подмены MIME-типов
add_header X-Content-Type-Options "nosniff" always;

# Строгая изоляция источника перехода
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# Принудительный HTTPS на 2 года
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;

# Ограничение доступа браузера к оборудованию
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;

# Content Security Policy (CSP)
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'none';" always;
```

## 4. Защита приложения и бизнес-логики (Application Pentest)

1. **Аутентификация мастера (Better Auth):**
   - Публичная регистрация отключена (`disableSignUp: true`).
   - Роль `admin` назначается только через консоль сервера (`npm run auth:create-admin`) или прямой SQL-запрос.
   - Сессионные куки помечены флагами `httpOnly`, `secure`, `sameSite: lax`.
   - Защита от Open Redirect в параметре `callbackUrl` (`sanitizeRedirectUrl`).

2. **Защита от подмены цен (Price Tampering):**
   - Клиент никогда не передаёт цену куклы на сервер.
   - Стоимость изделия и доставки рассчитывается сервером на основании актуальной записи в таблицах `products` и `site_settings`.

3. **Защита от перебора заказов (IDOR):**
   - Ссылка на подтверждение заказа использует криптографический UUIDv4 (`public_token`).
   - Перебор последовательных числовых ID (`/zakaz/1`, `/zakaz/2`) исключён архитектурно.
   - Попытки передать невалидный токен фильтруются до обращения к СУБД.

4. **Защита от ботов и спама:**
   - Формы заявок оснащены невидимым полем-ловушкой (Honeypot). Боты, заполняющие это поле, получают фиктивный ответ без сохранения в базу данных.
   - Встроенный Rate Limiter (не более 3 заявок за 10 минут с одного IP).

5. **Вебхуки платёжных шлюзов (bePaid / ЕРИП):**
   - Проверка подписи запросов через `crypto.timingSafeEqual` для устранения атак по времени (Timing Attacks).
   - Проверка идемпотентности по идентификаторам `transaction.uid` / `orderId`.

## 5. Резервное копирование и аварийное восстановление (Disaster Recovery)

- **Скрипт бэкапа:** [`deploy/scripts/backup.sh`](file:///home/ofi/DollShop/deploy/scripts/backup.sh)
  - Снятие атомарного дампа PostgreSQL (`pg_dump --clean --if-exists`).
  - Gzip-сжатие с максимальным коэффициентом 9.
  - Криптографическое шифрование по алгоритму **AES-256-CBC** с функцией вывода ключа **PBKDF2** (100 000 итераций).
  - Автоматическая ротация: удаление локальных копий старше 14 дней.
  - Поддержка выгрузки в изолированный бакет S3 в Беларуси.
- **Скрипт восстановления:** [`deploy/scripts/restore.sh`](file:///home/ofi/DollShop/deploy/scripts/restore.sh)
  - Расшифровка архива по ключу `BACKUP_ENCRYPTION_KEY`.
  - Безопасное восстановление схемы и данных без конфликтов (`--yes` для автоматизации).
  - Проверено тестами восстановления.
